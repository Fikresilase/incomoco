# Afaan Oromo TTS Validation Gate

## Current production behavior

The configured adapter is `OpenRouterTTS` using `google/gemini-3.8-flash-lite-tts` and voice `Kore`. The current `TTS_ALLOWED_LANGS` value is `am,en`; Oromo and Somali must remain unavailable until their speech is validated. The server-driven `/api/v1/voice/capabilities` response is the frontend source of truth.

The saved samples in [`voice_samples/`](voice_samples/) are for human evaluation. A successful synthesis request and playable WAV file are not proof of pronunciation quality or supported-language status. The configured Flash-Lite model's published language list does not establish Afaan Oromo support; do not turn Oromo on based only on the model accepting an Oromo prompt.

## Approval criteria

Before enabling Oromo, an Inkomoko-approved native Afaan Oromo speaker should review the saved Oromo sample and at least one fresh sample generated by the exact configured model and voice. Review should confirm that the speech is intelligible Afaan Oromo, not substituted English or Amharic, and that pronunciation is acceptable for the intended audience. Record the reviewer, date, model, voice, and decision with the evaluation artifacts. If the exact model's official documentation still omits Afaan Oromo, keep the capability disabled even when one sample sounds plausible; first confirm provider support for that model/version.

## Enable after approval

Only after both checks above pass:

1. Change the local `TTS_ALLOWED_LANGS` setting in `.env` to `am,en,om`. Do not change `.env.example` or the application default until this has been approved for the project environment.
2. Recreate the API and worker so they load the updated setting: `docker compose up -d --force-recreate api worker`.
3. Confirm `GET /api/v1/voice/capabilities` includes `om` and that Oromo Listen controls become available from that response.
4. Test Oromo playback through the existing `/api/v1/voice/speak-text` flow, then verify Amharic and English playback still work and that cached files remain separated by language, model, voice, and text.
5. If the Oromo review fails or the capability response is wrong, restore `TTS_ALLOWED_LANGS=am,en` and recreate `api` and `worker`.

No new endpoint or provider adapter is needed. The existing adapter already maps `om` to an Afaan Oromo instruction, while its configured allowlist gates availability.
